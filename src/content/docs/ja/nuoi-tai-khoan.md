5日間でシステムをマスターしました。この段階ではシステムは**自動で動きます**。あなたの仕事は**正しいものを正しいタイミングで観察し、うまくいっているものには触らない**こと。結果は5日では出ません。ここで、2〜4週間後に出ます。

> **この段階の問い:** 自分のアカウントは「生きて」いるか、そして毎日何をすべきか?
>
> 毎朝10分だけ。あとは忍耐です。

**毎朝10分 → サインを読む → その週の仕事をする → 自分で壊さない → 適切なタイミングでサポートに連絡**

## 毎朝 — 10分

毎日同じ順番で。各項目をチェック。

* [ ] **Control Center を開く** — **20台すべてオンライン**か? 落ちている端末は電源を挿し直し、2分待ってから再度 Scan([Day 1](/ja/a2-lo-trinh-mot-tuan/a4-ngay-1-phan-cung) 参照)。
* [ ] **Schedules を開く** — 昨夜のシナリオは**最後まで実行**されたか? エラー表示や途中停止のスケジュールはないか([Day 3](/ja/a2-lo-trinh-mot-tuan/a6-ngay-3-tu-dong) 参照)?
* [ ] **各端末をざっと見る** — **ログアウト**した端末、**認証を求められている**端末、見慣れない警告が出ている端末はないか?
* [ ] **記録に1行書く** — 日付 · オンライン台数 · 異常サインのあるアカウント数 · 行ったこと。1行でいい、ただし毎日。
* [ ] **何か変** → 下の*サイン*表を確認。不明なら [サポートに連絡](/ja/lien-he-ho-tro) — テンプレートに「育成 … 週目」を追記。

:::note[記録は何のため]
トラブル時、サポートの最初の質問は**「いつから?」**です。記録があれば5秒で答えられます。なければ推測になり、間違った箇所を直すことになります。
:::

## アカウントが生きているか問題があるかのサイン

| 生きている — そのままに | 要注意 — すぐ対処 |
| --- | --- |
| 毎日ログイン状態が安定 | 誰も触っていないのに**予期せずログアウト** |
| シナリオが毎晩最後まで実行される | シナリオが2晩連続で**途中停止** |
| 認証の要求がない | 数日のうちに**認証要求が繰り返される** |
| エンゲージメントと再生数が**ゆっくり着実に**伸びる | 2週間後も数字が**完全に横ばい**、または急落 |
| 端末1台にプロキシ1つ、重複なし | **複数のアカウントが同時に問題** |

:::danger[複数のアカウントが同時に死ぬ]
ほぼ確実に**プロキシの共有**、またはルーター / アイデンティティ層の不具合です — 運の問題ではありません。アカウントの追加を止め、[Day 2](/ja/a2-lo-trinh-mot-tuan/a5-ngay-2-danh-tinh) に戻って端末1台にプロキシ1つを確認してから再開してください。
:::

## 各週にやること

| 週 | やること | 完了の目安 |
| --- | --- | --- |
| **1週目**(Day 5 の直後) | **テスト用5アカウント**だけを動かす。観察し、記録し、**追加も変更もしない**。 | 5アカウントが**7日間**問題なく経過 |
| **2週目** | 5つが安定 → 残りを購入し **20台**に拡大、**端末1台にプロキシ1つ**。新しい端末ごとに [Day 2](/ja/a2-lo-trinh-mot-tuan/a5-ngay-2-danh-tinh) を繰り返す。 | 20台オンライン、シナリオが最後まで実行 |
| **3週目** | **設定を変えない。** プラットフォームと分野をまだ選んでいなければ [Day 4〜5](/ja/a2-lo-trinh-mot-tuan/a7-ngay-4-5-nen-tang) で選ぶ。 | 数字が**着実に**動き始める |
| **4週目** | 記録を見直す: どのアカウントが堅調で、どれが弱いか。維持・交換・拡大を決める。 | 自分の記録を読んで次の一手が分かる |

:::tip[なぜ20台に拡大する前に7日待つのか]
2日間平穏でも何も分かりません — 新規アカウントは通常3日目から7日目に精査されます。早く拡大するとリスクが4倍になります。
:::

## やってはいけないこと

* 数字が横ばいのうちに**設定を変え続ける** — アカウントには安定が必要。毎日変えると何が原因か分からなくなる。
* 節約のために**プロキシを共有する** — アカウントを一括で失う最速の方法。
* シナリオ実行中の端末を**手で操作しまくる** — 人と機械の混ざった挙動はフラグが立ちやすい。
* テスト用5アカウントが7日を経過していないのに**すぐ20台に拡大する**。
* **旧マニュアルのリンクからアプリをインストールする** — Day 2 の公式 APK フォルダだけを使う。

## サポートに連絡するタイミング

「あと数日様子を見る」のではなく、次のいずれかに当てはまったらすぐ連絡:

* 同じ日に**2つ以上のアカウント**に問題
* スケジュールを確認したのにシナリオが**2晩連続で停止**
* 電源を挿し直して Scan しても端末が**オフラインのまま**
* 原因不明の**認証要求の繰り返し**

[定型テンプレート](/ja/lien-he-ho-tro) を使い、1行追加:

```
- 育成段階: ... 週目 · 問題は ... から(記録より)
```

## 完了の目安

:::tip[完了の目安]
20アカウントが**2〜4週間**大きな問題なく経過し、シナリオが毎晩実行され、数字がゆっくり着実に伸びている。ここで初めて [Day 4〜5](/ja/a2-lo-trinh-mot-tuan/a7-ngay-4-5-nen-tang) の目的にシステムを使います。
:::

:::caution[公開前に GenFarmer が記入する項目]
以下の具体的な水準はプラットフォームとチームの実際の経験に依存するため、創作していません。記入後、このボックスを削除してください。
* 新規アカウントの**推奨1日アクション量**(視聴、いいね、コメント…)をプラットフォーム別に
* プラットフォーム別の**具体的な「死亡」サイン**と、**アカウントを交換するか再育成するか**
* **4週目以降**にお客様がすべきこと — box の追加、適したオートメーションパッケージ
:::

## よくある3つのミス

| ✕ | ミス | 結果 |
| - | --- | --- |
| 1 | 焦って毎日シナリオを調整する | アカウントが不安定になり、どの変更が原因か分からない |
| 2 | テスト用5アカウントが2日平穏だっただけで20台に拡大 | データ不足 — 3〜7日目に一括で失うリスク |
| 3 | 記録をつけない | サポートの「いつから?」に答えられず、間違った箇所を直す |
